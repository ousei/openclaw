# 多语言响应规则

## 🎯 核心规则

**用户使用什么语言提问，就用什么语言回答。**

## 规则说明

### 基本原则

1. **自动检测用户语言**: 根据用户消息的语言特征自动识别
2. **匹配响应语言**: 使用相同的语言回复
3. **保持一致性**: 在整个对话中保持语言一致性

### 常见语言

- **中文** (简体/繁体): 用户使用中文提问 → 用中文回答
- **English**: 用户使用英文提问 → 用英文回答  
- **日本語**: 用户使用日语提问 → 用日语回答
- **其他语言**: 根据用户使用的语言回复

## 示例

### 场景 1: 中文提问

```
用户: "看一下现在的天气"
助手: "正在为您查询天气信息..."
      "找到了以下天气信息：..."
```

### 场景 2: English Question

```
User: "What's the weather in Tokyo?"
Assistant: "Searching for weather information..."
          "Here's the weather for Tokyo:..."
```

### 场景 3: 日本語質問

```
ユーザー: "今の天気を見てください"
アシスタント: "天気情報を検索しています..."
            "東京の天気情報です：..."
```

## 特殊情况处理

### 1. 混合语言

如果用户在同一消息中使用多种语言，优先使用主要语言（出现频率最高的语言）。

### 2. 代码和技术术语

**重要**: PowerShell 命令关键字必须使用英文（这是技术限制）：

- ✅ **正确**: `Get-ChildItem`, `Sort-Object`, `Format-Table`
- ❌ **错误**: `获取子项`, `排序对象`, `格式化表格`

但解释和说明可以使用用户的语言。

**示例**:
```
用户: "列出文件"
助手: "使用 Get-ChildItem 命令列出文件..." (中文解释，英文命令)
```

### 3. 用户明确要求

如果用户明确要求使用特定语言，遵循用户要求。

**示例**:
```
用户: "Please answer in English" (即使之前用中文)
助手: "Sure, I'll answer in English from now on."
```

## 实施指南

### 检测方法

1. **字符集检测**: 
   - 中文字符（简体/繁体）→ 中文
   - 日文字符（ひらがな/カタカナ/漢字）→ 日语
   - 主要英文字符 → 英文

2. **关键词检测**:
   - 中文关键词: "的"、"是"、"在"、"查看"、"查询"
   - 日语关键词: "です"、"ます"、"ください"、"見て"
   - 英文关键词: "the"、"is"、"what"、"please"

3. **上下文**: 考虑对话历史中的语言使用

### 响应构造

1. **使用相同语言**: 构造回复时使用检测到的语言
2. **保持自然**: 使用该语言的自然表达方式
3. **技术术语**: 代码、命令、API 名称保持原样（通常是英文）

## 注意事项

### ✅ 应该做的

- 根据用户语言自动切换响应语言
- 保持对话中的语言一致性
- 技术命令使用英文，但用用户语言解释
- 代码注释可以使用用户的语言

### ❌ 不应该做的

- 不要强制使用单一语言
- 不要忽略用户的语言偏好
- 不要在用户使用中文时强制用英文回答
- 不要在用户使用英文时强制用中文回答
